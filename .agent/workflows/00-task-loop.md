# 00 任务闭环

读者：AI
类型：流程
权威：接一个任务时的固定动作顺序
状态：2026-11-03 建立
依赖：`../../AGENT.md`、`../../docs/README.md`、`../../TODO.md`

## 1 开工前（≤ 3 份文档）

1. 读 `AGENT.md` §2 红线（已在上下文里就跳过）。
2. 按 `docs/README.md` §1 的清单**只取一份**相关文档，再取它的下游契约。
3. 看 `TODO.md` §2 该任务对应的 `T-NN`；若任务不在 TODO 里，先补进 TODO 再动手。

**禁止通读 `docs/`**：9 份文档全读一遍会让人误以为看懂了，实际丢失的是判据。

## 2 动手顺序（改代码的任务）

```
① 判据先定  —— 先把"怎么算过"写出来（引用 verification.md 的断言 / 门禁判据）
② 契约再改  —— 若要改字段/语义，先改 docs/ 对应文档
③ 实现后补  —— core → cabi → 绑定 → 演示页，逐层往下
④ 双端同批  —— 动了 core 必须同批跑双端等价
⑤ 台账收尾  —— TODO 删条目、DECISION 追加、RECORD 待登记
```

## 3 收尾自检

- [ ] 判据可执行（有命令、有期望值、有容差）
- [ ] 没有在绑定层写电气规则
- [ ] 数值全 `f64`；没有 `f32`
- [ ] 同一输入两次求解结果字节一致
- [ ] 每个接点都给齐 4 个 `f64` ＋ `flags`
- [ ] `docs/` 有无需同步的口径（有就同批改）
- [ ] `TODO.md` 完成项已删除；新发现的歧义已登记 `P-NN`
- [ ] 产物未入库

## 4 遇到歧义怎么办

**停下，登记，不自选。**

在 `TODO.md` §1 追加 `P-NN`（下次可用编号接在最后），写清：问题、候选与代价、我方倾向、影响哪些文档、阻塞什么。然后去做**不依赖这个口径**的部分。

## 5 遇到"看起来对但不确定"怎么办

用 `solver.md` §1 的五条根因当检查表逐条过一遍（索引映射、迭代收敛、单位复数、矩阵重排、奇异处理）。五条都排除之后再怀疑实现。
