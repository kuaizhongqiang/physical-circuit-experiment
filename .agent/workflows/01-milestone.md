# 01 里程碑推进与门禁

读者：AI
类型：流程
权威：怎么推进 M0–M5、怎么判一个门禁到底过没过
状态：2026-11-03 建立
依赖：`../../docs/roadmap.md`（唯一判据来源）、`../../TODO.md`

## 1 一次只推进一个里程碑

本文件不重复里程碑内容 —— 判据一律查 `docs/roadmap.md` §3 的 `G0…G5`。这里只规定**动作顺序**。

## 2 推进一个里程碑

```
1. 确认上一门禁已过（没过的里程碑不许开下一个）
2. 把该里程碑的 T-NN 逐条转成 GitHub issue（用 task.yml 模板）
3. 每完成一条：跑判据 → 删 TODO 条目 → 关 issue
4. 全部 T-NN 清零后，跑门禁判据（roadmap §3 的 G?）
5. 门禁过 → 提交 → RECORD 登记 → 开下一个里程碑
```

## 3 门禁判定规则

- **判据必须能贴出原始输出**：命令 ＋ 返回码 ＋ 关键行。禁止"我跑过了，没问题"。
- **任一必过项失败即门禁不过**，不能靠"其余都过了"折算。
- **门禁不过但代码已写了**：保留代码、不合并里程碑、把失败项拆成新 issue；**不许降低判据**去迁就实现。
- 门禁判据本身要改 → 属口径变更，进 `TODO.md` §1 待拍板。

## 4 已经踩过的坑（每次推进前扫一眼）

| 坑 | 表现 | 处置 |
|---|---|---|
| 提前铺案例 | 器件还没齐就写 `fixtures/` 期望值，返工两遍 | 先器件后案例（`roadmap.md` §4） |
| 把"已知不覆盖"当 bug | C8 能耗制动电流恒为 0 | 查 `verification.md` §5 再动手 |
| 演示页倒逼改接口 | 演示页先做，然后 ABI 反复改 | ABI 定稿在演示页之前（M3 < M4） |
| 用例只验一种工况 | 星三角只测了切换后的稳态 | 每类电路至少一条"故障注入"反例 |

## 5 里程碑收尾必须做的三件事

1. `RECORD.md` 登记本批提交（`R-NN`）。
2. `TODO.md` 该里程碑条目清零；新发现项入 §1 或 §2。
3. 若门禁改了判据 → 回写 `docs/roadmap.md` 并说明改动原因。
